### **What Exactly Is Shadow AI and Why Has It Become a $670k (and $10.22M) Problem?**

Shadow AI is any AI tool or workflow adopted by employees without security approval, governance, or visibility. In 2026 this includes not just ChatGPT or Claude, but AI agents with browsing or file-system access.

The critical technical frontier is **indirect prompt injection** (OWASP LLM01:2025 and confirmed in large-scale 2026 red-teaming). Because many shadow tools lack sandboxing or output validation, an attacker can embed malicious instructions in a webpage, PDF, or email that the AI later reads. The model then follows those hidden instructions — exfiltrating data, changing configurations, or initiating unauthorized actions — while the employee sees only a normal-looking summary.

**The 4 Primary Attack Surfaces (arXiv:2604.08304):**

1. **Retrieval Layer** — Poisoned or manipulated documents injected into the knowledge base  
2. **Prompt Layer** — Indirect prompt injection through retrieved content  
3. **Generation Layer** — Model manipulation or data exfiltration via crafted outputs  
4. **Integration Layer** — Insecure APIs, logging, or data flows between components

Without proper controls, an attacker can trick the system into revealing sensitive information, generating malicious outputs, or even executing unauthorized actions.

### **The 6-Stage Secure RAG Pipeline (Technical Lead Framework)**

According to the leading 2026 research, a secure RAG system should include these stages:

| Stage | Security Control | Purpose |
| ----- | ----- | ----- |
| 1\. **Ingestion** | Document sanitization \+ provenance tracking | Prevent poisoned data from entering the system |
| 2\. **Indexing** | Access control \+ encryption at rest | Protect sensitive content during storage |
| 3\. **Retrieval** | Query filtering \+ relevance scoring \+ rate limiting | Block malicious or out-of-scope queries |
| 4\. **Augmentation** | Prompt guardrails \+ output validation | Prevent prompt injection and data leakage |
| 5\. **Generation** | Model access controls \+ logging \+ redaction | Control what the LLM can see and output |
| 6\. **Response** | Post-processing filters \+ audit trails | Catch and log any policy violations |

**Technical Fringe in 2026:** Many organizations are rushing RAG deployments without these controls, creating what researchers call “wide-open knowledge exfiltration vectors.” The NIST TREC 2025 RAG evaluation framework now explicitly tests for these vulnerabilities.
